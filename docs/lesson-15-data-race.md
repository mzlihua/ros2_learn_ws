### 0.1 这一关要回答的问题

1. **两份重叠的副本同时碰同一个数字，最后那个数字对不对？**
2. **如果不对，错在哪一步？** —— 错的是"读"、"加"、还是"写回"？
3. **回调组那把"锁"能不能顺手保护这个数字？**（第 13/14 关一直在用它挡人）
4. **想修的话，锁要加在【哪一层】？加几把？加在哪几行？**

⭐ 问题 3 是本关的题眼，也是本关最容易想当然的一格。
前十四关一直在问"**谁挡住谁**"（调度）；**这一关第一次问"撞上了会怎样"（数据）。**

| 关 | 问的是 | 量的是 |
|---|---|---|
| 第 12 关 | 有几个**线程**在跑 | 调度 |
| 第 13 关 | 谁和谁**共用一把锁** | 调度 |
| 第 14 关 | 同一个回调会不会**和自己**撞上 | 调度 |

### 0.2 理论背景（答题时边答边翻）

#### (a) 三层楼：本关第一次往下走一层

前四关一直在往上数楼层（进程 → 线程 → 回调组），**本关掉头往下走**：

| 层 | 谁住在这一层 | 它管什么 | 出处 |
|---|---|---|---|
| **进程** | 容器 / 执行器 | 有**几只手** | 第 12 关 |
| **节点** | **回调组** | 同一只手**能不能再拿一次**（调度） | 第 13 关 |
| **你的代码** | **`std::mutex`** | 同一块**数据**能不能被两只手同时碰 | **第 15 关** ← 就是这儿 |

⭐ 一句话：**回调组那把闸门，管到"谁先跑"为止；再往下"跑的时候动没动坏东西"，它一个字都不管。**

#### (b) 把两个"锁"分清楚（本关最容易混的地方）

课上前后出现过**两样东西**都被人叫过"锁"，它们**一点关系都没有**：

| | 回调组那一把 | 本关要用的那一把 |
|---|---|---|
| 名字 | `can_be_taken_from_`（一个原子布尔） | `std::mutex` |
| 住在哪 | **执行器**的调度流程里 | **你自己那个类**里（成员变量） |
| 在哪个文件 | `rclcpp/callback_group.hpp:266` | 你的 `.cpp` |
| 管什么 | **能不能再拿一次**（调度） | **谁能碰这块数据**（数据） |
| 谁置的 | rclcpp 内部 | 你，自己写 |
| 类型 | `std::atomic_bool` | `std::mutex` |
| **它保护你的变量吗** | ❌ **一个字都不管** | ✅ **就干这一件事** |

`rclcpp/callback_group.hpp:259`（对照组身子上那把真锁）：

```cpp
mutable std::mutex mutex_;                     // 组身上确实有一把真 mutex
std::atomic_bool can_be_taken_from_;           // :266 上面说的那道具闸门
```

⚠️ **`mutex_` 保护的也不是你的数据** —— 它保护的是组里那几份**名单**
（`subscription_ptrs_` / `timer_ptrs_` 这些 vector），**你回调里读写的任何东西它都不管**。

> ⇒ 所以本关**不能**因为"我把回调挂在互斥组上了"就说数据安全了。
> **互斥组管的是"同一时刻只跑一份"；它没说要跑的那份东西归谁管。**

#### (c) 一行 `+= 1` 在机器上不是一步

`count_ += 1` 看着像一句话，翻译成人能执行的动作是**三步**：

| 步 | 干什么 | 拿的是什么 |
|---|---|---|
| 1 | **读** | 把 `count_` 现在的值抄到自己手里 |
| 2 | **加一** | 手心里的数 +1 |
| 3 | **写回** | 把手心里的数放回 `count_` |

⚠️ **三步中间任何一处都可以被另一只手插进来。** 两只手各做一遍就可能：

```
两只手都读到 5  →  各自加一  →  都写回 6     ← 加了两次，只涨了 1
```

⭐ 关键：**它不报错。** 程序照跑，日志照打，只是**数字不是你以为的那个**。

#### (d) 三个词的定义（本关的词汇骨架）

| 词 | 定义 | 关键在哪 |
|---|---|---|
| **数据竞争**（data race） | 两个线程**同时**碰**同一块内存**，其中**至少一个在写**，而且**没有任何同步** | "没有任何同步"是判据 |
| **临界区** | 一段**不能**被两个线程同时执行的代码 | 就是"读 → 加工 → 写回"这三步合起来 |
| **原子性**（atomic） | 一个**不可分割**的操作 —— 中间塞不进任何人 | `+= 1` **不是**原子的 |

⚠️ **临界区的边界是"整段"，不是"那一行"。** 这是本关加锁时最容易加错的地方：

| 加锁的写法 | 保护住了什么 |
|---|---|
| 只把 `shared_ = local;` 那一行包进 `lock_guard` | ❌ 读和写回之间照样能被人插进来 |
| 把 **读 → 加工 → 写回** 三行**一起**包进同一个作用域 | ✅ 这三步之间没人能进来 |

#### (e) 数据竞争的后果：不是"慢一点"，是**【没定义】**

- C++ 标准对**数据竞争**这件事的说法是 **未定义行为**（undefined behavior，UB）——
  意思是标准**没有规定**该发生什么。
- ⇒ **"加两次只涨了 1"只是它的一种表现**，不是承诺。别的可能：
  读到半截的值、读到某个**永远不会被写出来**的数、被编译器优化掉、或者这一次对下一次错。

| 不是 | 是 |
|---|---|
| "数会少一点"（像个可以估的误差） | "**标准没规定**" —— 具体多少跟调度走，同一份代码跑两次可以不一样 |
| "每次跑都这样" | **可能这次错、下次对**（所以只跑一次不算证据） |

⚠️ 还有一条**反直觉的**：编译器看你的代码时，如果觉得某个变量"中间没人动它"，
**可以把它一直放在寄存器里**、不每次都回内存读。所以"我把变量声明成 `int`，别的线程总该看得见吧" ——
**不成立**。这也是为什么 C++ 给了一个专门的类型（见 (g) 的 `std::atomic`）。

#### (f) 这一关为什么能把"偶发"变成"必然"

真实程序里，两只手真正**撞上**的窗口通常只有**几纳秒** —— 所以数据竞争常常表现为
"**偶尔**错一次，重跑又对了"，极难抓。

本关的手法只有一个字：**把窗口撑开。**

| | 真实世界 | 本关的仪器 |
|---|---|---|
| "读"到"写回"之间隔多久 | 几纳秒 | **一次 `sleep`** |
| 撞上的概率 | 偶尔 | 必然 |

⭐ **这是手艺，不是结论**：`读 → 睡 → 加一 → 写回` 里那个"睡"**不是 bug 的一部分**，
它只是让原本看不见的东西**变得肉眼可见**。
⇒ **看到的现象是假的（睡出来的），但它证明的规则是真的（真的没有原子性）。**

⚠️ 配套前提（第 14 关已实测）：**可重入组 + 多线程 + 睡 1.5 秒**这个组合下，
**同一个回调的两份副本会同时在跑** —— 本关**直接用**这条，不再重测。

#### (g) 要自己补的那把锁（API + 一句为什么）

| 写法 | 意思 |
|---|---|
| `std::mutex m_;` | 声明一把锁 —— **必须是成员变量**（跟着对象活；局部变量出作用域就没了） |
| `std::lock_guard<std::mutex> lock(m_);` | **进作用域自动拿锁，出作用域自动放锁** |

⭐ **锁保护的从来不是"变量"，是"访问"。** 一句必须记住的话：

> **没有任何变量"属于"某把锁。是"每一个要碰它的地方，都得拿同一把锁。"**
>
> ⇒ 少写一处 `lock_guard`，等于这处根本没锁。**加锁是"每处都要"，不是"加一次就行"。**

| `lock_guard` 的名字来自哪 | |
|---|---|
| `lock` | 它替你锁 |
| `guard`（守卫） | 它**替你守着"放锁"这件事** |

这套写法的学名叫 **RAII**：把"放锁"绑在"离开作用域"上 ——
于是**你不可能忘记放锁**（哪怕中间 `return` 了、或者抛异常了）。

| 还有两个同族的（本关只需认识名字） | 差别 |
|---|---|
| `std::unique_lock<std::mutex>` | 更灵活（能中途解锁、能搬来搬去），代价是慢一点 |
| `std::atomic<int>` + `fetch_add(1)` | **完全不同的路子**：不锁，而是让"加一"这**一个动作**本身不可分割 |

⚠️ **最后那一行是本关最容易想错的一格**：`std::atomic` 让**一个操作**变原子。
它没说"你那一整段"变原子。**它管得比 `mutex` 窄**（加练实验 D 就是冲这个来的）。

#### (h) 一句"翻译"：`rclcpp::sleep_for` 睡的是**线程**，不是回调

`/opt/ros/lyrical/include/rclcpp/rclcpp/utilities.hpp:235`，头文件原话：

| 原文（英文） | 翻译 |
|---|---|
| Use the global condition variable to block for the specified amount of time. | 用全局条件变量，阻塞**指定的这段时间**。 |
| This function can be interrupted early if the associated context becomes invalid due to `shutdown()` or the signal handler. | 如果上下文因为 `shutdown()` 或信号处理而失效，这个睡眠**可能提前结束**。 |

⭐ 两点，都跟本关有关：

1. **它睡的是"执行这段代码的那条线程"** —— 第 12 关叫"手"。
   ⇒ 两份重叠的副本，睡的是**两条不同的手**（前提：手 ≥ 2）。
   ⇒ **这正是"睡 1.5 秒"能把窗口撑开 1.5 秒的原因。**
2. ⚠️ 它**不是** `std::this_thread::sleep_for` 的别名 —— 它走的是 rclcpp 自己那套条件变量，
   **可以被 shutdown 打断**。（顺带解释：Ctrl+C 之后那些"睡到一半就醒了"的日志。）

#### (i) 词汇表（英文我翻好）

| 英文 | 中文 | 记忆点 |
|---|---|---|
| data race | 数据竞争 | race = 赛跑，**两只手在抢同一个数** |
| critical section | 临界区 | **不能**被同时执行的那段 |
| atomic | 原子的 | 字面：**切不开的** |
| `std::mutex` | 互斥量 | mutual（互相）+ exclusion（排斥），**和第 13 关那个词同源** |
| `std::lock_guard` | 锁守卫 | 见 (g) |

| undefined behavior（UB） | 未定义行为 | **标准没说会怎样** —— 比"错"更严重 |
| fetch_add | 取出并加 | `std::atomic` 的原子加一 |
| non-atomic | 非原子的 | 中间塞得进人 |

### 0.3 这次会动的旋钮 + API 形状

#### 旋钮（**一档只动一个**）

| 旋钮 | 现在（第 14 关收尾） | 本关会拧到 | 管哪一格 |
|---|---|---|---|
| **组的类型** | `Reentrant` | **不动**（可重入） | 锁（回调组）= 没有 |
| **容器** | 多线程 | 多线程 / **单线程** | 手：16 / 1 |
| **睡多久** | `1500ms` | **不动** | —— 只是把窗口撑开 |
| 🆕 **回调体里那一步** | `count_a_ += 1;`（**一行**） | **拆成四行**（读 → 睡 → 加一 → 写回），两个回调**碰同一个数** | 🆕 **数据** |
| 🆕 **代码层的锁** | 无 | **加 / 不加** | 🆕 **数据** |

⭐ **本关的两根新旋钮管的是同一格（数据）** —— 前十四关那两格（手 / 锁）本关**都不拧**，
它们是**背景**：撑着"两份副本同时在跑"这个舞台（第 14 关实验 B 已实测）。

#### API 形状（英文我翻好）

**要拆成的一行** —— 从：

```cpp
shared_ += 1;
```

拆成：

| 行 | 干什么 | 本关会再多加一步 |
|---|---|---|
| 1 | **读** | `int local = shared_;` |
| 2 | （本关**插进来的那一步**） | `rclcpp::sleep_for(1500ms);` |
| 3 | **加一** | `local += 1;` |
| 4 | **写回** | `shared_ = local;` |

**要补的那把锁**（实验 B 用）：

```cpp
#include <mutex>          // 加在文件最上面的 include 区

std::mutex m_;                                    // 成员变量：一把锁

{
    std::lock_guard<std::mutex> lock(m_);         // 进作用域拿锁
    int local = shared_;                          // 读
    rclcpp::sleep_for(1500ms);                    // 睡（窗口）
    local += 1;                                   // 加一
    shared_ = local;                              // 写回
}                                                 // 出作用域自动放锁
```

**加练要用到的另一个路子**（实验 D 用）：

```cpp
#include <atomic>         // 加在文件最上面的 include 区

std::atomic<int> shared_{0};                      // 原子整数
shared_.fetch_add(1);                             // 原子的"加一"
```

#### 要动手改的地方

`src/hello_ros_cpp/src/sleeper_component.cpp`：

| 改哪 | 现在 | 改成 |
|---|---|---|
| **`tick_a` / `tick_b` 的函数体** | 各碰自己那个 `count_x_`，只做"印 → 睡 → 印" | 两个都改成**碰同一个 `shared_`**，走上面那四步，并且**每一步都印一行日志** |
| **成员变量区** | `int count_a_; int count_b_;` | 留下计拍用的，再加一个**两个回调共用**的 `int shared_;` |
| **构造函数的 `count_x_ = 0;`** | 两句 | 加一句 `shared_ = 0;` |

⚠️ **本关的日志是本关唯一的尺子** —— 每一步都要印出来，行数要能对上：

```
[A] 第1拍 读到 shared=0
[A] 第1拍 写回 shared=1
```

⚠️ 改 `.cpp` **必须重新 build**，而且**必须先 Ctrl+C 杀掉容器**（第 14 关坑 3：
`.so` 不会热重载，新旧版本的装载回执**一模一样**，光看回执分不出跑的是哪一个）。

### 0.5 实验预告（**只给做法，不给结果**）

#### 本关的尺子（同一把尺子，**第四次换参照物**）

> 同一份日志里，盯每一次 **`写回 shared=N`** 前面的那一行 **`读到 shared=N-1`**：
>
> **有没有两个不同的"第 X 拍"，读到的是同一个数？**
> 有 = 有一份副本的加一**被吃掉了**（它写回的和别人一样）。

⭐ 第 12 关盯的是**另一个节点**的行；第 13 关是**同一节点的另一个定时器**；
第 14 关是**它自己的下一拍**；**本关盯的是那个数本身**。

#### 还有一个"能算出来的预期"（本关最漂亮的一格）

> **每一拍加一 ⇒ 最后那个 `shared_` 应该等于"总共跑了几拍"。**

⚠️ 这个数是**能自己算出来的**（周期 1 秒 × 跑了多久 × 几个定时器）——
**能算出来的东西才叫预期**。先把它写在纸上，再跑。

#### 前置动作（老规矩，**两头都要做**）

#### 实验 A：**不加锁**，先看看会怎样

| | |
|---|---|
| 装什么 | 改造后的 `Sleeper`（两个定时器都碰同一个 `shared_`），**多线程**容器，可重入组照旧 |

## 2. 核心概念

### 2.1 尺子：`④ = 写回的行数 ÷ 最后的 shared_`

"④"这个记号沿用第 12–14 关：**一个能一眼判"重叠了没有"的读数。**

| ④ | 意思 | 白写了几条 |
|---|---|---|
| `1/1` | 一条写回涨一格 | 0 条（干净） |
| `1/2` | 两条写回涨一格 | 一半 |
| `1/4` | 四条写回涨一格 | 四分之三 |

⚠️ 为什么"写回的行数"能当数、而"拍号"不能 —— §2.4。

### 2.2 第一个结果：`1/4 = 1/2 × 1/2`

第一轮拿到的 `1/4` 不是一个"结果"，它是**两个一半叠起来的**：

| 折半 | 谁和谁撞了 | 判它的那对数 | 单独拧开它（实测） |
|---|---|---|---|
| **①** | **A 和 B**（两个定时器）几乎同时开跑 | 两个"第 1 拍"的时间戳差多少（实测 **0.0002 秒**） | §7 实验 A″：只剩 A → `1/2` 变 `1/1` |
| **②** | **同一个回调的相邻两拍**重叠 | `觉`（1.5s） vs `周期`（1.0s）—— 觉 > 周期就叠 | §7 实验 A′：`觉` → 500ms → `1/4` 变 `1/2` |

⭐ 最后一列是本关最漂亮的地方：**两个 1/2 各归一个旋钮，一格一格拧开、每一格都验过。**

### 2.3 量具也被污染了：日志标签错位**升格**

第 14 关 §2.5 那个"日志标签错位"，当时只是**现象**。
本关它爬到了**量具**身上 —— 你要数"跑了几拍"，可日志里那个**拍号**本身长在 `count_a_` 上，而 `count_a_` 也在被争：

```
[A] 第1拍 读到 shared=0     ← 副本① 开跑，count_a_ 从 0 变 1
[A] 第2拍 读到 shared=0     ← 1.5 秒后副本② 开跑，count_a_ 从 1 变 2
[A] 第2拍 写回 shared=1     ← 副本① 醒了 —— 可它印出来的是【副本②】的号
```

⭐ 所以**副本① 那次写回，日志里根本找不到"第 1 拍 写回"这一行** —— 它的号被后来者顶掉了。

⚠️ 副产物：`觉 < 周期` 时**标签会自己对齐**（第 14 关那个指纹蒸发了）—— 因为不重叠了，也就没有后到的号来顶它。

### 2.4 拍号不能当拍数 —— 尺子升级表

| 想数什么 | 拿什么数 | 行不行 |
|---|---|---|
| 跑了几拍 | 数日志里的**拍号** | ❌ 号本身在被争 |
| 跑了几拍 | 数 **`写回` 的行数** | ✅ 一份副本恰好印一行，不多不少 |
| 某一拍的 +1 有没有被吃掉 | 同一拍 `读到 shared=N-1` / `写回 shared=N` 成对看 | ✅（§0.5 那把尺子，仍然有效） |
| **跑了多久** | **最后一个时间戳 − 第一个时间戳** | ✅（新增，见 §8 坑 4） |
| **A 和 B 是不是都还在跑** | **分开数 A / B 的写回条数** | ✅（新增，见 §2.7） |

### 2.5 锁的位置 = **段**（不是那一行）

同一个 `std::lock_guard`，放在三个不同位置，**实测出三种结果**：

| 锁放在哪 | 实际保护了什么 | 实测 ④ |
|---|---|---|
| 函数**最后一行**（`}` 前面） | **空气**（它后面 0 行代码） | `1/4`（= 完全没加） |
| **只包** `shared_ = local;` 那一行 | 只保护了"写"这一个动作 | `1/4`（= 完全没加） |
| 包住 **读 → 睡 → 加一 → 写回** | 整段临界区 | **`1/1`** ✅ |

⭐ 一句话落点：

> **`lock_guard` 的作用范围 = "从它那一行，到它所在的花括号结束"。**
> 那 1.5 秒的"睡"只要还在锁**外面**，锁就什么都没守住。

⚠️ 而且这三轮**编译器不报错、程序照跑、日志照打** —— 又一个"不报错的坑"（第 13 关那课的家族）。

### 2.6 题眼：回调组的锁按**【组】**分，数据的锁按**【数据】**分

这是 §0.1 问题 3 的答案。实测两轮：

| 配置 | 谁挡得住谁 | 实测 ④ |
|---|---|---|
| **两个**互斥组（A 一把、B 一把） | A 挡得住 A 自己；**A 挡不住 B** | `1/2` —— **还是丢一半** |
| **同一个**互斥组（都在 `group_a_`） | 谁都挡得住谁 | `1/1` —— 但 **A 被饿死**（0 条） |

⭐ 落点：

> **回调组那把锁，挡的是"挂在同一把组上的代码"。**
> A 和 B 碰的是**同一块数据**，手里却拿着**两把不同的锁** —— 在回调组眼里它俩毫无关系。
>
> ⇒ 清点一下事实：这里 **数据 1 个，锁 2 把**。**锁比数据多，就漏。**

这正好接上 §0.2(g) 那句：**没有任何变量"属于"某把锁。要求是"每一个要碰它的地方，都得拿同一把锁"。**

### 2.7 ⭐ 判据会失效（第 14 关那一课复活了）

`④ = 1/1` 是"指标回到正常值"。但它有**两种完全不同的来源**：

| 来源 | 哪一轮 | A / B 都还在跑吗 |
|---|---|---|
| **真的保护了数据** —— 两只手照跑，只是排队 | `std::mutex` 包住四步 | ✅ A **17** 条 / B **7** 条 |
| **把第二个写者干掉了** | 同一个互斥组（A 饿死）；或只开 1 个定时器 | ❌ A **0** 条 |

⇒ 所以**光看 ④ 分不清"修好了"和"饿死了"。** 必须加一把尺子：**分开数 A / B 的写回条数。**

第 14 关 §2.3 是第一次"判据会失效"（只有**间距**能把"锁拦的"和"手拦的"拆开）。
本关是同一件事的第二次：**`④` 分不清，分开数 A / B 才分得清。**
—— 这就是为什么 §2.4 的表里要**加两把新尺子**。

## 3. 完整代码

本关定稿 = **基准版**：四步（读→睡→加一→写回）＋ 可重入 ×2 ＋ 多线程容器 ＋ 1500ms ＋ **不加锁**。
§7 的七个实验，全是在这份基准上**只动一处**得到的。

文件：[src/hello_ros_cpp/src/sleeper_component.cpp](../src/hello_ros_cpp/src/sleeper_component.cpp)

✅ **仓库里现在放的就是这份定稿** —— 收工时已把实验 E 那个只包最后一行的 `lock_guard` 清掉、TODO 注释清空，
**留一份干净的基准**（想复现 §7 任何一轮，照 §3.2 的表动一处即可）。

```cpp
#include <chrono>
#include <memory>

#include "rclcpp/rclcpp.hpp"
#include "rclcpp_components/register_node_macro.hpp"

using namespace std::chrono_literals;

// 第 15 关的"记账仪"：第 12/13/14 关那台"测速仪" + 一个【两个回调共用的数】。
//   ① 两个定时器都碰同一个 shared_
//   ② 每拍对 shared_ 做的不是一句 += 1，而是四步：读 → 睡 → 加一 → 写回
//      （"睡"是量具：把原本几纳秒的窗口撑到 1.5 秒，让看不见的竞争变成必然）
class Sleeper : public rclcpp::Node
{
public:
    Sleeper(const rclcpp::NodeOptions & options) : Node("sleeper", options)
    {
        count_a_ = 0;
        count_b_ = 0;
        shared_ = 0;                       // 两个回调共用的那个数

        group_a_ = this->create_callback_group(rclcpp::CallbackGroupType::Reentrant);
        group_b_ = this->create_callback_group(rclcpp::CallbackGroupType::Reentrant);
        timer_a_ = this->create_wall_timer(1s, [this]() { tick_a(); }, group_a_);
        timer_b_ = this->create_wall_timer(1s, [this]() { tick_b(); }, group_b_);
    }

private:
    void tick_a()
    {
        count_a_ += 1;

        int local = shared_;                                          // 读
        RCLCPP_INFO(this->get_logger(), "[A] 第%d拍 读到 shared=%d", count_a_, local);
        rclcpp::sleep_for(1500ms);                                    // 睡
        local += 1;                                                   // 加一
        shared_ = local;                                              // 写回
        RCLCPP_INFO(this->get_logger(), "[A] 第%d拍 写回 shared=%d", count_a_, local);
    }

    void tick_b()
    {
        count_b_ += 1;

        int local = shared_;
        RCLCPP_INFO(this->get_logger(), "[B] 第%d拍 读到 shared=%d", count_b_, local);
        rclcpp::sleep_for(1500ms);
        local += 1;
        shared_ = local;
        RCLCPP_INFO(this->get_logger(), "[B] 第%d拍 写回 shared=%d", count_b_, local);
    }

    rclcpp::TimerBase::SharedPtr timer_a_;
    rclcpp::TimerBase::SharedPtr timer_b_;
    rclcpp::CallbackGroup::SharedPtr group_a_;
    rclcpp::CallbackGroup::SharedPtr group_b_;
    int count_a_;
    int count_b_;
    int shared_;            // 两个回调共用的那个数
};

RCLCPP_COMPONENTS_REGISTER_NODE(Sleeper)
```

### 3.1 唯一"对的"那一版（实验 B 结尾）

有两种错法（§2.5 表里前两行），和一种对法 —— 对法只有一处不同：

```cpp
    void tick_a()
    {
        count_a_ += 1;

        {                                                     // ← 花括号一开
            std::lock_guard<std::mutex> lock(m_);             //   拿锁（RAII）
            int local = shared_;                              //   读
            rclcpp::sleep_for(1500ms);                        //   睡（窗口）
            local += 1;                                       //   加一
            shared_ = local;                                  //   写回
        }                                                     // ← 花括号一闭，自动放锁

        RCLCPP_INFO(this->get_logger(), "[A] 第%d拍 写回 shared=%d", count_a_, local);
    }
```

还想让 `RCLCPP_INFO` 也进锁？那就得把它**挪到花括号里面**。本关的定稿把它留在外面 —— 反正它不碰 `shared_`。

### 3.2 本关每一轮改了哪一行

| 轮 | 只改这一处 | 实测 ④ |
|---|---|---|
| 实验 A（基准） | —— | `1/4` |
| 实验 A′ | `sleep_for(1500ms)` → `500ms`（两处） | `1/2` |
| 实验 A″ | 注释掉 `timer_b_` 那一行 | `1/1` |
| 实验 B（错的位置 ①） | 两个回调体**末尾**各加一行 `lock_guard` | `1/4` |
| 实验 B（错的位置 ②） | `lock_guard` **只包** `shared_ = local;` | `1/4` |
| 实验 B（**对的**） | 花括号包住**四行** | **`1/1`** |

## 7. 实测现象与结论 ⭐

七轮，同一条尺子。**每一轮只动一处**。

### 实验 A · 基准：完全不管数据

**配置**：可重入 ×2 ／ 多线程 ／ 1500ms ／ 两个定时器 ／ **无锁**

**日志片段**（节选）：

```
[179068...] [A] 第1拍 读到 shared=0
[179068...] [B] 第1拍 读到 shared=0      ← A、B 几乎同时（差 0.0002 秒）
[179068...] [A] 第2拍 读到 shared=0      ← 1.5 秒后，同一份副本又来了一拍
[179068...] [A] 第2拍 写回 shared=1      ← 第 1 拍醒了，号却是【第 2 拍】的
[179068...] [B] 第2拍 写回 shared=1
```

**读数**：16 秒 / **32 条写回** / 末值 **8** ⇒ `④ = 32 ÷ 8 = 4` ⇒ **`1/4`**

**结论**：

- 两份副本都**读到 0**、都**写回 1** —— 第二份的工作被第一份盖掉，**白写**。
- 值的序列是 `1,1,2,2,3,3,…` —— **两两相等**，一眼就看出重叠。

### 实验 A′ · 把"觉"从 1500ms 拧到 500ms

**只改**：`rclcpp::sleep_for(1500ms)` → `500ms`（两处）

**日志片段**：

```
[1790688746.953863366] [A] 第1拍 读到 shared=0
[1790688747.454410624] [A] 第1拍 写回 shared=1     ← 差 0.5005 秒 ✅
```

**读数**：**40 条写回** / 末值 **20** ⇒ `④ = 2` ⇒ **`1/2`**（比 A 好一半）
值变成 `1,2,3,4,5,…`，**标签也自己对齐了**。

**结论**：

- `觉`（0.5s）< `周期`（1.0s） ⇒ 同一个回调的**相邻两拍不再重叠** ⇒ 折半② 关掉。
- 剩下的 `1/2` 全是折半①（A 和 B 各写一遍同一个值）。
- ⚠️ 这一轮**同时暴露了一件事**：`觉 < 周期` 时**日志标签错位消失**了 —— 说明那个指纹是重叠的**果**，不是因。

### 实验 A″ · 只留 A（把 B 拆掉）

**只改**：注释掉 `timer_b_ = ...` 那一行

**读数**：**20 条写回** / 末值 **20** ⇒ `④ = 1` ⇒ **`1/1`**
每一拍 `读到 shared=N-1` → `写回 shared=N`，**一条不落**。

**结论**：

- 折半①（两个写者）关掉，`1/2` → `1/1`。
- 一拍只花 0.50 秒，周期 1.0 秒 ⇒ **同一只手的前后两拍碰不上** ⇒ **这不叫数据竞争**（一个写者，没有"并发"）。
- ⇒ **`1/4` 的两个因，各自被单独关掉过一次，都成立。**

### 实验 B · 加锁（这次要试**三个位置**）

#### B-① 锁在函数**末尾**

**只改**：两个回调体 `}` 前各加一行 `std::lock_guard<std::mutex> lock(m_);`

**读数**：**与实验 A 一模一样** ⇒ **`1/4`**

**结论**：锁后面**一行代码都没有** —— 它守在空气里。**等于没加。**

#### B-② 锁只包 `shared_ = local;`

**只改**：花括号只包住**最后一行**

**读数**：**52 条写回 / 末值 13** ⇒ `④ = 4` ⇒ **`1/4`**（**与实验 A 仍然一模一样**）

**结论**：只保护了"写"**这一个动作** —— 但**1.5 秒的窗口在锁外面**。
读的时候没锁、睡的时候没锁、加一的时候没锁 ⇒ 醒来照样把过期的值写回去。**等于没加。**

#### B-③ 锁包住**四步**（对的）

**只改**：花括号包住 `读 → 睡 → 加一 → 写回`

**日志片段**：

```
[1790690023...] [A] 第1拍 读到 shared=0
[1790690024.500...] [A] 第1拍 写回 shared=1
[1790690026.000...] [B] 第1拍 读到 shared=1      ← B 排在 A 后面（被锁挡住）
[1790690027.500...] [B] 第1拍 写回 shared=2
[1790690029...] [A] 第2拍 读到 shared=2
...
```

**读数**：**24 条写回** / 值 `1..24` **一条一条按序** ⇒ **`1/1`**
**A 17 条 / B 7 条** —— 两个**都还在跑** ✅
每条间隔 `1.5004 秒`，总时长 **36.016 秒**（24 × 1.5）。

**结论**：

- 锁包住整段 ⇒ **读到的和写回的成了"一件事"**，中间没人能插进来。
- `1/4` → `1/1`，**且两个写者都活着** —— 这才是**真的保护了数据**（对照 §2.7）。
- ⚠️ 代价：现在**真的排队**了，所以慢了（36 秒 vs A 的 16 秒）。

### 实验 C · 换回调组：两个**互斥**组

**只改**：`Reentrant` → `MutuallyExclusive`（两处）

**读数**：**70 条写回** / 末值 **35** ⇒ `④ = 2` ⇒ **`1/2`**
**A 35 条 / B 35 条**。每 1.5 秒**成对撞一次**。

**结论**（题眼的一半）：

- 互斥组只是让"**同一个组内**"的代码排队 —— **A 和 B 在两个组里，两把锁互不相干**。
- ⇒ 还是丢了一半。**回调组的锁按【组】分，不按【数据】分**（§2.6）。

### 实验 D · 并成**一把**锁（`timer_b_` 也挂 `group_a_`）

**只改**：`timer_b_ = ... group_a_);`（两个定时器共用 `group_a_`）

**读数**：**17 条写回** / 末值 **17** ⇒ `④ = 1` ⇒ **`1/1`** —— 但 **A 只有 0 条、B 有 17 条**
时长 25.5 秒（17 × 1.5）。

**结论**（题眼的另一半，也是本关最值钱的一条）：

- 并成一把锁，**谁真的挡住了谁** —— 数据是不丢了。
- 但 **A 被彻底饿死**（0 条）：两个定时器 1 秒一次、而每个回调要占锁 1.5 秒 ⇒ **锁永远轮不到 A**。
- ⇒ **`④ = 1/1` 有两种来源**（§2.7）。**光看 ④ 分不清"修好了"和"饿死了"。**
- ⇒ 这就是 §2.4 里加"**分开数 A / B**"这把尺子的原因。

### 实验 E · 回到可重入，锁**只包最后一行**（复验）

**只改**：组改回 `Reentrant` ×2，`lock_guard` 只包 `shared_ = local;`（即 B-② 的配置 + 可重入）

**读数**：**52 条写回** / 末值 **13** / **A 26 条 / B 26 条** / 时长 25.3 秒
⇒ `④ = 4` ⇒ **`1/4`** —— 与实验 A **一模一样**。

**结论**：复验 §2.5 —— **锁只包一行 = 等于没锁**（窗口在锁外面）。
⚠️ 收尾 Ctrl+C 时多打了几行（A×2、B×2）—— `rclcpp::sleep_for` 睡的是**线程**，会**被关机中断**（§0.2(h)）。

### 七轮总表

| 轮 | 组的类型 | 觉 | 代码层的锁 | ④ | A / B 都跑吗 | 备注 |
|---|---|---|---|---|---|---|
| A | 可重入 ×2 | 1500ms | 无 | **1/4** | ✅ | 16 秒 / 32 条 / 末值 8；值 `1,1,2,2…` |
| A′ | 可重入 ×2 | **500ms** | 无 | **1/2** | ✅ | 读→写回 = 0.5005s；值 `1,2,3,4…`；**标签对齐** |
| A″ | 只有 A | 500ms | 无 | **1/1** | 只有 A | 读 N-1 → 写 N 一条不落；**不重叠 ⇒ 不是数据竞争** |
| B-① | 可重入 ×2 | 1500ms | 锁在**函数末尾** | **1/4** | ✅ | 守在空气里，**等于没锁** |
| B-② | 可重入 ×2 | 1500ms | 锁只包**最后一行** | **1/4** | ✅ | 窗口在锁外，**等于没锁** |
| B-③ | 可重入 ×2 | 1500ms | 锁包**四步** | **1/1** | ✅ A17/B7 | 24 条 / 值 1..24 / 每条 1.5004s / 时长 36.016s |
| C | **互斥 ×2** | 1500ms | 无 | **1/2** | ✅ A35/B35 | 70 条 / 末值 35；每 1.5s 成对撞一次 |
| D | **互斥 ×1**（同一把） | 1500ms | 无 | **1/1** | ❌ **A=0（饿死）** | B 17 条 / 25.5 秒 |
| E | 可重入 ×2 | 1500ms | 锁只包**最后一行** | **1/4** | ✅ A26/B26 | 52 条 / 末值 13；**与 A 一模一样** |

**三条落地结论：**

1. **`1/4` 拆成 `1/2 × 1/2`** —— 折半①（A/B 同时开跑，差 0.0002s）＋ 折半②（同拍两副本重叠，`觉`>`周期`）。两个因**各归一个旋钮**，各被单独关掉验过（A′、A″）。
2. **锁按【数据】加，不按【组】加，而且必须包住整段。** 锁在组上 ⇒ 漏一半（C）；只包一行 ⇒ 等于没锁（B-②、E）。
3. **`④ = 1/1` 会骗人** —— 真的保护（B-③）和把写者饿死（D）读数一样。**必须分开数 A / B。**

## 8. 踩坑记录

### 坑 1 · 改完 "以为改了" 就跑（本关**连续两次**）

- 第一次：`1500ms → 500ms`。跑出来**跟上一轮一模一样**。
- 第二次：`group_b_ → group_a_`。跑出来**又**跟上一轮一模一样。

**病根**：改完没确认，就跑。
**药**：§5.1 的 `grep -n` 自查 —— **跑之前先看一眼那几行**。（还有 `.so` 不热重载：改 `.cpp` 不改 `.h` 也**必须**重编 + 重启容器。）

### 坑 2 · 锁 "守在空气里"

`lock_guard` 写在函数 `}` 前 —— 它后面一行代码都没有。
**药**：§2.5 —— 作用域是"那一行 → 它所在的 `}`"。**要么包住该包的段，要么别写。**

### 坑 3 · 拿"日志行数"当时间

问"读和写回差了几秒"，答"**3**"（数了 3 行日志）。
**药**：日志是**事件流**，不是时间轴。要时间就用**时间戳相减**（§5.2）。

### 坑 4 · 跑了多久凭感觉（本关**连续两次**）

- 第一次：预测 "a 打 2 拍、b 打 2 拍"（12 秒），实际 **16 秒 / 16 拍** —— 定时器在回调**睡的时候照常触发**（第 14 关 §2.4）。
- 第二次：预测 13（20 秒），实际 **36 秒**（24 × 1.5）—— 结果**是对的**，可他说"还是不对"。

**药**：**跑了多久不许凭感觉 —— 从日志里量**（最后一个时间戳 − 第一个时间戳）。

### 坑 5 · `#include <mutex>` 被顺手删了

加锁那一版编译报 `std::lock_guard` 不认 —— 因为 `<mutex>` 那行不在了。
**药**：`lock_guard` / `std::mutex` 都在 `<mutex>` 里。**加锁先看头文件。**

### 坑 6（我的）· §0.3 没说清"锁的作用域 = 花括号"

§0.1 问题 4 问的是"**加在哪几层**"，他概念**答对了**（"他的边界是以段为边界的"），可**放的时候**把 `lock_guard` 放到了函数末尾。
**药**：§0.3 只给了 API 形状，**没给"作用域"**。已在 §2.5 补上 —— 这是**我**的漏，不是他的。

### 坑 7 · "只包最后一行" 看着像在保护

直觉上"写回时加锁"很安全，实测 **= 没加**（B-②、E）。
**药**：**临界区是"读→写回"这一整段**，不是"写回"那一行。
