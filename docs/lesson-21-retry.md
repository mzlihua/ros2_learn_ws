## 0. 预习 ⭐

>
> **边界判据（每句话都要过一遍）：把那句话换一个旋钮，它还对吗？**
> 还成立 = **理论** → 写；只对这一个场景成立 = **结果** → 不写。

| 例 | 是理论还是结果 | 写不写 |
|---|---|---|

### 0.1 这一关要回答的问题

⇒ 第 20 关那句「只有一条路」**只验了一条路**。本关去问：**还有没有第二条？**

所以本关要问的是：

3. ⭐ 只试**一次**（失败就拉倒）和**一直试到成功**，差在哪？
4. ⚠️ 第 15 / 20 关那把旧尺子（`④`），在哪一版上**先坏掉**？为什么？

⭐ **题眼**：第 20 关问的是「**一个工具的作用范围**」；本关问的是 ——

### 0.2 理论背景（答题时边答边翻）

#### (a) ⭐ 词表（英文我翻好）

| 词 | 意思 | 本关里对应什么 |
|---|---|---|
| **比较交换**（compare-and-swap，**CAS**） | 先比一下"现在是不是我以为的那个值"，是就换成新的，不是就**告诉我现在是谁** —— 整件事**一气呵成** | `compare_exchange_strong` |
| **期望值**（expected） | 我以为现在是多少 | 第 ① 步读到的那个值 |
| **新值**（desired） | 我想把它改成多少 | `local + 1` / `expected + 1` |
| **尝试**（attempt） | 一次 CAS | 循环里的**每一圈** |
| **重试**（retry） | 失败之后再试一圈 | `while` 的下一次 |
| **无锁**（lock-free） | 没人"排队等锁"；失败的人自己退回去重来 | 本关的 C 版 |
| **乐观**（optimistic） | 先干，干完再检查；不对就重来 | CAS 这条路 |
| **悲观**（pessimistic） | 先占住，别人别进来 | `mutex` 这条路 |

#### (b) ⭐ CAS 的一次尝试到底做了什么

`compare_exchange_strong(expected, desired)` 一次做三件事，**中间塞不进任何人**：

| 现在 `shared_` 是 | 我带来的 `expected` | 它做什么 | 返回 | 之后 `expected` 变成 |
|---|---|---|---|---|
| **等于** expected | 0 | 把 `shared_` 换成 `desired` | `true` | 不变 |
| **不等于** expected | 0 | **不动** `shared_` | `false` | ⭐ **现在真实的值** |

⭐⭐ **第二行是这一关的命根子**：
失败的时候它**不是只回一句"失败"** —— 它顺手把「现在到底是多少」塞回你的 `expected` 里。

（这不是我猜的，是读出来的：`/usr/include/c++/15/bits/atomic_base.h:1007` 有一句注释，
英文原文是 `Only allowed to modify __e on failure, so make a copy`，
翻过来：**"只允许在失败时改 `__e`（就是 expected），所以先做一份副本"**。
⚠️ 那句注释在 `__atomic_impl` 里 —— 那是**非整数类型**走的路；`atomic<int>` 走的是另一条
（`__atomic_base<_ITp>`，**589 行**），但用的是同一个 GCC 内建 `__atomic_compare_exchange_n`，
**规则一样**：失败时把现值写回第一个参数。）

#### (c) ⭐ 为什么「一条指令」和「一整圈循环」不是一回事

```text
        ┌──────── 一次 CAS（原子）────────┐
  → 比 →│ 比：现在 == expected？            │
        │ 是 → 换成 desired                 │  ← 这三下之间塞不进人
        │ 否 → 不动，把现值写回 expected    │
        └───────────────────────────────────┘
                          ↓
              ┌── 这里是【空地】──┐   ← 别的线程可以改 shared_
                          ↓
                  下一圈：再 CAS 一次
```

⭐ 一条 CAS 是**一次**；外面那层 `while` 是**好多圈**。
**圈与圈之间，`atomic` 一个字都没管** —— 和第 20 关「两道墙之间是空地」是同一句话。

⚠️ **CAS 还留了一个坑，本关不会撞上，但要知道名字**：**ABA 问题**。
你读到 `A`，别人把它改成 `B`、又改回 `A`；你的 CAS 一看"还是 `A`"，以为没人动过。
—— 本关的更新是**只加不减**的，值回不去，所以撞不上。**记下名字，挂账。**

#### (d) ⭐⭐ 三条路：安全从哪来

| 路子 | 靠什么不出错 | 别人来的时候 | 失败了怎么办 | 能护住"不是 +1"的更新吗 |
|---|---|---|---|---|
| **`mutex`** | **排除**：这一段里只有我 | **排队**（挂起、让出 CPU） | 不会失败 | ✅ 能 |
| **`fetch_add`** | **合并**：根本没有段 | 各做各的 | 不会失败 | ❌ 只能做它自带的那几种（加 / 减 / 与 / 或 / 异或 / 换值） |
| **CAS 循环** | ⭐ **检测**：每一圈都验一次 | **不排队**，自己重来 | **重读、重算、再试** | ✅ 能（只要更新能从"现在的值"重新算出来） |

⭐ 一句话：

> **正确不一定靠"不被打断"；也可以靠"打断了能发现"。**

#### (e) ⭐⭐ 硬件对照 —— 这条路他在 STM32 上已经走过了

第 20 关 §0.2(e) 那张表的延长线：

| 单片机上的写法 | 本关对应 | 护到哪 |
|---|---|---|
| `__disable_irq()` … `__enable_irq()`（关中断包住一段） | `std::mutex` + 花括号 | 从关到开之间的**全部** |
| 一条 `LDREX` / `STREX`（Cortex-M 的独占访问） | `compare_exchange_strong` 的**一次** | **那一次**比较+交换 |
| ⭐ **`do { old = __LDREXW(&count); new = old + 1; } while (__STREXW(new, &count));`** | ⭐ **本关的 CAS 循环** | **每一圈**各管各的，整段**不原子** —— 但**不会丢** |

⭐⭐ 那个 `do … while` 他**写过**：`STREX` 返回非 0 就是"刚才有人插了一手，重来"。
**桌面上的 CAS 循环，就是它的同一套思路**：不排除别人，只**发现**别人来过、然后重算。
（第 20 关那句「知识点是同一个，只是换了一层皮」，本关再验一次。）

⚠️ 还是那句不能照搬：单片机常常是**单核**，独占监视器管得住；
本机是 **16 核**。本关**不拧** `memory_order` 这个旋钮（保持默认 `seq_cst`），
要把"多核下光有 CAS 够不够"留给以后。

### 0.3 这次会动的旋钮 + API 形状

⚠️ **本关还是代码关** —— 动的只有 `sleeper_component.cpp`（现在仓库里是第 15 关基准版）。

| 旋钮 | 从 | 到 | 动的是哪一格 |
|---|---|---|---|
| `shared_` 的**类型** | `int shared_;` | `std::atomic<int> shared_{0};` | 访问的粒度（同第 20 关） |
| **写回**的动作 | `shared_ = local;`（**无条件**写） | `compare_exchange_strong(...)`（**有条件**写：先验再写） | ⭐ 本关真正的旋钮：**写之前先验一下** |
| **失败之后** | —— | **B：拉倒 ／ C：重来** | ⭐⭐ **本关的题眼：一圈 ↔ 一直试** |

**API 形状**（英文我翻好；这里只给"它长什么样"）：

```cpp
bool compare_exchange_strong(int& expected, int desired);

// 参数 1：expected —— 我以为现在是几（⚠️ 必须是【变量】，不能是常数/表达式）
// 参数 2：desired  —— 我想把它改成几
// 返回值 ：true  = 比对上了，换成功
//          false = 没换（现在不是我带来的那个值）
// ⚠️ 失败时：参数 1 会被【改写】成"现在真实的值"  ← 这一条是循环能写对的关键
```

**B 版（只试一次，失败就拉倒）的形状：**

```cpp
int expected = local;                                  // 我读到的那个值
shared_.compare_exchange_strong(expected, local + 1);  // 只试这一次，返回值不要
```

**C 版（一直试到成功）的形状：**

```cpp
int expected = local;
while (!shared_.compare_exchange_strong(expected, expected + 1)) {
    // 失败：expected 已经变成"现在真实的值" —— 拿它重新算、再试一圈
}
```

⭐ **B 和 C 的唯一区别：外面那层 `while`。** 同一句 CAS、同一个 `atomic`、同一个窗口。

**⭐ 一条设计前提（先说死，免得跑出两种数据）：**

| 问题 | 本关的规矩 | 为什么 |
|---|---|---|
| 重试的那几圈，**还要不要睡 1500ms**？ | ❌ **不睡** —— 睡只在第 ① 步读完之后睡**一次** | 睡是**量具**（把窗口撑开），不是操作的一部分；重试再睡，一拍要 1.5×n 秒，拍数就乱了 |
| CAS **失败**了，要不要打一行 `写回`？ | ❌ **不打** —— "写回"这行只在**真的写进去**时出现 | 日志要能当尺子用：一行 `写回` = 一次成功的写 |
| 想在日志里**看见重试**怎么办？ | 在 `while` 里加一行（⏎ 见下） | 这一关不光要量"对不对"，还要量"**被打断过没有**" |

**想看见重试，就在 `while` 里加这一行（形状）：**

```cpp
RCLCPP_INFO(this->get_logger(), "[A] 第%d拍 重试（现在是 %d）", count_a_, expected);
```

⚠️ 有了这一行，日志里会多出一类行 —— **它们不是"写回"**。数的时候别混。

**【查】API 的查法（这一格是【查】的，不是【推】的）：**

```bash
grep -n "compare_exchange_strong" /usr/include/c++/15/bits/atomic_base.h | head
```

要找两处：

| 找什么 | 在哪 | 为什么 |
|---|---|---|
| 签名 `bool compare_exchange_strong(__int_type& __i1, __int_type __i2, memory_order __m = …)` | **589 行**（在 `__atomic_base<_ITp>` 里，338 行开始） | 第一个参数是**引用** —— 所以它**改得动**你的变量；**第三个参数有默认值** |
| 注释 `Only allowed to modify __e on failure, so make a copy` | **1007 行** | 失败时会改写 expected（§0.2(b) 那张表的第二行）；⚠️ 这是**非整数**那条路的注释，规则一样 |

⚠️ **同一个函数名在头文件里出现了好几次 —— 每次属于不同的【类型特化】**。
找的时候不能只看函数名，要**同时核对类型名**：

| 你看到的名字 | 是哪个类型 | 行号（本机 g++ 15） |
|---|---|---|
| `__int_type& __i1` | ⭐ **整数**（`atomic<int>` 走这个） | **589** |
| `_Fp& __expected` | **浮点**（`atomic<float>` / `atomic<double>`） | 1398 |
| `_Tp* __ptr` / `_Val<_Tp>& __expected` | **指针**（`atomic<int*>`） | 1126 |
| `_Tp& __expected` | **`atomic_ref`**（对一个**普通变量**做原子访问） | 1603 |

> 换台机器路径可能不是 `15`：先 `ls /usr/include/c++/` 看一眼版本号，再拼路径。

**改哪几行（先分类，别一行一行盯）：**

| 基准版里是什么 | 在哪 | 一共几处 | 是 声明／清零／读／写 里的哪一种 | B / C 版怎么改 |
|---|---|---|---|---|
| `int shared_;` | 83 | 1 | **声明** | `std::atomic<int> shared_{0};` |
| `shared_ = 0;` | 30 | 1 | **清零** | **删掉**（`{0}` 已经干了） |
| `int local = shared_;` | 44、**64** | **2** | **读** | `int local = shared_.load();` |
| `local += 1;` | 52、**70** | **2** | **算**（改的是自己手里那份） | 不再单独写成一句 —— 交给 CAS 的 `desired`（`local + 1` / `expected + 1`） |

## 1. 本关目标

1. 看清**一次 CAS** 到底做了什么：成功 / 失败 / 失败后 `expected` 变成什么。
2. 把「**只试一次**」和「**一直试到成功**」分开量（B vs C）。
3. 补一把新尺子（`④'`），并抓出旧尺子 `④` 的**第三种 `1/1`**。

⭐ 一句话：第 20 关问「**墙围到哪**」，本关问「**墙不够长的时候，是不是非得把段拆掉**」。

## 2. 核心概念

### 2.1 一次 CAS = 三件事，中间塞不进人

| 现在 `shared_` | `expected` | 动作 | 返回 | `expected` 之后 |
|---|---|---|---|---|
| **等于** | 0 | 换成 `desired` | `true` | 不变 |
| **不等于** | 0 | **不动** | `false` | ⭐ **现在真实的值** |

⭐ 最后那格是命根子：失败不只是"告诉你失败"，它把**现值**塞回你手里。

### 2.2 ⭐ 一条指令 ≠ 一整圈循环

- 一次 CAS 是原子的。
- 外面那层 `while (!cas)` 是**好多圈**；圈与圈之间是**空地**。
- **本关实测**：C 版 3 轮的重试次数 **23 / 26 / 24** —— 这就是"两圈之间别人改过"的**直接读数**。
  ⇒ 循环**不原子**，这次是**量到**的。

### 2.3 ⭐⭐ 不原子 ≠ 会丢

C 版被其他人插了 23~26 次，**一拍没丢**（20 拍 → 20）。

为什么？三件事：

1. **每圈都验** —— CAS 比较"现在还是不是我手里这个值"。
2. **失败能发现** —— 返回 `false`，并把现值写回 `expected`。
3. **下一圈按新值重算** —— `expected + 1` 用的是**刚拿回来的数**，不是 1.5 秒前的旧数。

⇒ 段不需要"切不开"；它需要"**可重试**"。

### 2.4 三条路：安全从哪来

| 路子 | 靠什么 | 别人来的时候 | 能不能护住"不是加法"的更新 |
|---|---|---|---|
| `mutex` | **排除** | 排队 | ✅ 能 |
| `fetch_add` | **合并**（段消失） | 各做各的 | ❌ 只能做它自带的那几种 |
| **CAS 循环** | ⭐ **检测 + 重试** | 不排队，自己重来 | ✅ 能（只要更新能从当前值重算） |

⚠️ **第 20 关那句话要升级**：

| 第 20 关（只验了一条路） | 本关 |
|---|---|
| 想把 `atomic` 管一段，**只有一条路**：把段改造成**一次** | 还有第二条：把段改造成 **「一次 + 重试」** —— 段不用消失，只要每次尝试都能验、失败了能重算 |

### 2.5 硬件对照

`LDREX/STREX` 的重试循环就是 CAS 循环：

```c
do {
    old = __LDREXW(&count);
    new = old + 1;
} while (__STREXW(new, &count));   // 非 0 = 被打断 = 重来
```

`__disable_irq` 包一段 = `mutex`；一条 `STREX` = 一次 CAS；`do … while` = 本关的 C 版。

### 2.6 ⭐ 尺子：旧 `④` 的盲区

| 版 | 读到 | 写回 | 终值 | 旧 `④` = 写回÷终值 | 新 `④'` = 终值÷拍数 | 丢 |
|---|---|---|---|---|---|---|
| A | 20 | 20 | 5 | 20/5 = **4**（`1/4`） | 5/20 = **1/4** | 15 |
| **B** | 20 | 5 | 5 | 5/5 = **1** ⚠️ | 5/20 = **1/4** | 15 |
| **C** | 20 | 20 | 20 | 20/20 = **1** | 20/20 = **1** | **0** |

⭐ **B 版旧尺子给 `1/1`，实际和 A 一样烂。** 为什么？

- 旧尺子的分子（`写回`）和分母（终值）**都只由"成功的写"组成**；
- 失败的那 15 拍在**两个数里都不出现** ⇒ 从测量里**完全隐身**。

⇒ **第 7 次判据失效**，`1/1` 的**第三种来源**：**放弃**（前两种：真保护 / 饿死写者）。

新尺子 `④'` 的分母是**总拍数**，失败拍子跑不掉。

## 3. 完整代码

基准 = 第 15 关那份（四步、Reentrant ×2、多线程容器、1500ms、不保护）。
本关只动 `shared_` 那一格 ＋ "写回"那一步。**A / B 两个回调各改一份。**

### 3.1 B 版 —— CAS 只试一次

```cpp
#include <atomic>                       // 顶部

std::atomic<int> shared_{0};            // 声明；构造函数里的 shared_ = 0; 删掉

int local = shared_.load();             // 第 ① 步（A / B 各一处）
rclcpp::sleep_for(1500ms);              // 第 ② 步不动
// local += 1;  删掉 —— 加一挪进 desired

int expected = local;                   // "我以为现在是几"
if (shared_.compare_exchange_strong(expected, local + 1)) {
    RCLCPP_INFO(this->get_logger(), "[A] 第%d拍 写回 shared=%d", count_a_, local + 1);
}
```

⚠️ `写回` 日志必须在 `if` **里面** —— 只有真的写进去了才记账。

### 3.2 C 版 —— CAS 循环

```cpp
int expected = local;
while (!shared_.compare_exchange_strong(expected, expected + 1)) {
    RCLCPP_INFO(this->get_logger(), "[A] 第%d拍 重试（现在是 %d）", count_a_, expected);
}
RCLCPP_INFO(this->get_logger(), "[A] 第%d拍 写回 shared=%d", count_a_, expected + 1);
```

⚠️ **三处和 B 不同**：

| 从 B 到 C | 为什么 |
|---|---|
| `if` → `while (!…)` | 失败就再来一圈 |
| `local + 1` → **`expected + 1`** | 每失败一次 `expected` 都变成新值，desired 必须跟着重算 |
| `写回` 日志搬到 `while` **外面**，打 `expected + 1` | 循环结束 = 已经写成功了 |

## 7. 实测现象与结论 ⭐

跑法：`/tmp/run21.sh <标签>`（10 秒一轮，每轮重开容器，SIGTERM 收工，`pgrep -c compo` 收工自查 = 0）。

### 7.1 原始数（A 1 轮 / B 3 轮 / C 3 轮）

| 版 | 轮 | 读到 | 写回 | 重试 | 终值 | 旧 `④` | 新 `④'` | 丢 |
|---|---|---|---|---|---|---|---|---|
| A 不保护 | a1 | 20 | 20 | 0 | 5 | **4**（`1/4`） | **1/4** | 15 |
| B CAS 一次 | b1 | 20 | 5 | 0 | 5 | **1** | **1/4** | 15 |
| B | b2 | 20 | 5 | 0 | 5 | **1** | **1/4** | 15 |
| B | b3 | 20 | 5 | 0 | 5 | **1** | **1/4** | 15 |
| C CAS 循环 | c1 | 20 | 20 | **23** | 20 | **1** | **1** | **0** |
| C | c2 | 20 | 20 | **26** | 20 | **1** | **1** | **0** |
| C | c3 | 20 | 20 | **24** | 20 | **1** | **1** | **0** |

预测 vs 实测：

| 格 | 押 | 实测 | 判 |
|---|---|---|---|
| B 旧 `④` | `1/1` | `5/5 = 1` | ✅ |
| B 新 `④'` | `< 1`（例子 `0.6`） | `5/20 = 0.25` | ✅ 方向对，比例子更低 |
| C 旧 `④` | `1/1` | `20/20 = 1` | ✅ |
| C 新 `④'` | `1/1` | `20/20 = 1` | ✅ |

### 7.2 ⭐ B 版：旧尺子的满分是假的

```text
20 拍 → 写回 5 行 → 终值 5
旧 ④ = 5 ÷ 5 = 1/1          ← 看起来完美
新 ④' = 5 ÷ 20 = 1/4        ← 和 A（完全不保护）一模一样
```

B 版 3 轮**全是** `5/20`：20 拍里只有 5 拍"恰好没人动过"，写成功；另外 15 拍**直接放弃**。

⭐ 旧尺子的盲区：分子分母**都只数成功的写**，失败的 15 拍**在两个数里都不出现**。
⇒ `1/1` 的**第三种来源**：**放弃**。

### 7.3 ⭐⭐ C 版：被打断 23~26 次，零丢失

```text
20 拍 → 重试 23/26/24 次 → 写回 20 行 → 终值 20
新 ④' = 20 ÷ 20 = 1/1
```

- **重试次数 > 0** ⇒ 两圈之间别人**确实改过** ⇒ 循环**不原子**（量到的，不是推的）。
- **终值 = 拍数** ⇒ 一拍没丢。

机制（§2.3）：每圈验 → 失败发现并拿回现值 → 下一圈按新值重算。

### 7.4 结论

> **CAS 保的是「比」和「换」那一次；循环那一段不原子。**
> **但循环不原子 ≠ 会丢** —— 只要每圈都能验、打断能发现、下一圈按新值重算。
>
> **安全不只来自「不被打断」（`mutex` / `fetch_add`），**
> **也可以来自「打断了能发现」（CAS 循环）。**

第 20 关的「只有一条路」在这里被**修正**：第二条路 = **把段改造成「一次 + 重试」**，段不用消失。

### 10.2 加练（想再拧一格的话）

- **D 版**：C 版 ＋ 在 `写回` 那行加"第几次尝试" —— 重试次数就是**冲突**的读数。
- **E 版**：把更新从 `+1` 换成"**取大的那个**"（`max`）—— `fetch_add` 干不了这件事，CAS 循环照样能。
- **F 版**：C 版 ＋ `thread_num:=1` —— 一只手时重试应该是 **0 次**。
