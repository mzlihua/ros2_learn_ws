# 第 14 关 · 可重入组（回调会不会和自己撞上？）

> 第 11 关掀掉「一个节点 = 一个进程」，第 12 关掀掉「一个节点 = 一只手」，
> 第 13 关掀掉「一个节点 = 一把锁」—— 三关问的都是同一个问题：**谁挡住谁？**
>
> 第 13 关停在**两把锁**上（两个互斥组，两道闸门）。
> 本关问的是闸门的**第四档**：如果这一格不是"锁有几把"，而是**根本没有锁**呢？
>
> 这话听着像"更自由"，但第 7 关早就说过答案的一半：
> **可重入组 = 允许重叠，不是允许并行。**
> 本关是把这句话按在**同一个回调**身上，看它到底成不成立 ——
>
> > **`tick_a` 的第 1 拍还没睡醒，第 2 拍能不能已经开始睡了？**
>
> 这是十三关以来第一次出现这种问法：**前十三关，参照物一直是"别人"。**

### 0.1 这一关要回答的问题

1. **同一个回调，能不能和"它自己"同时跑？**
   （`tick_a` 的第 2 拍，会不会在 `tick_a` 第 1 拍的 `睡醒了` **之前**就开始睡？）
2. **可重入组动的是哪一格？** —— 是把锁从 1 把变成 2 把，还是**把这一格整个撤掉**？
3. **如果它真能和自己重叠，谁该负责不撞车？**
   前十三关一直在问"谁挡住谁"，这一关第一次要问：**没人挡了怎么办？**

⭐ 问题 1 是本关的题眼。它和第 13 关问的**不是一回事** —— 只差一个参照物：

| 关 | 问的是 | 参照物 |
|---|---|---|
| 第 12 关 | 两个**不同节点**的回调能同时跑吗 | 另一个节点 |
| 第 13 关 | **同一个节点**的两个回调能同时跑吗 | 同一个节点的**另一个**定时器 |
| **第 14 关** | **同一个回调**的一拍和它自己的下一拍能同时跑吗 | **它自己的下一拍** |

### 0.2 理论背景（答题时边答边翻）

#### (a) 回调组的类型只有**两个档**

`/opt/ros/lyrical/include/rclcpp/rclcpp/callback_group.hpp:46`

```cpp
enum class CallbackGroupType
{
  MutuallyExclusive,
  Reentrant
};
```

翻译：**互斥** 或 **可重入**，二选一。
第 13 关一直在用第一档（`MutuallyExclusive`），本关拧到第二档（`Reentrant`）。

⚠️ **类型是创建时定死的**（头文件原话：*when creating one the type must be specified*），
**建好之后改不了** —— 想换档只能换一个组。

#### (b) 头文件对两档的**定义**（本关最该背下来的一段）

同一文件 `:64` 起。英文原文 + 翻译：

| 原文（英文） | 翻译 |
|---|---|
| Callback Groups have a type, either 'Mutually Exclusive' or 'Reentrant' and when creating one the type must be specified. | 回调组有个类型，要么「互斥」要么「可重入」，创建时**必须指定**。 |
| **Callbacks in Reentrant Callback Groups must be able to:** | **可重入组里的回调必须能做到：** |
| – **run at the same time as themselves (reentrant)** | – **和它自己同时跑**（reentrant 这个词的字面意思） |
| – run at the same time as other callbacks in their group | – 和**同一个组**里的其它回调同时跑 |
| – run at the same time as other callbacks in other groups | – 和**别的组**里的回调同时跑 |
| **Callbacks in Mutually Exclusive Callback Groups:** | **互斥组里的回调：** |
| – **will not be run multiple times simultaneously (non-reentrant)** | – **不会同时跑多份**（非可重入） |
| – will not be run at the same time as other callbacks in their group | – 不和**同组**的其它回调同时跑 |
| – **but must run at the same time as callbacks in other groups** | – **但必须**能和**别的组**的回调同时跑 |

⭐ 第一行 `run at the same time as themselves` 就是本关的题眼：
它说的**不是"另一个回调"，是"它自己"**。

⚠️ 最后一行那个 `but must`（但**必须**）也是定义的一部分：
互斥组关掉的**只是"组内"这道门**，**组与组之间它管不着** —— 这正是第 13 关第 5 行那一格。

#### (c) 那把"锁"在源码里到底是什么？

**不是 `std::mutex`。是一个原子布尔，一道闸门。**

`callback_group.hpp:266`

```cpp
std::atomic_bool can_be_taken_from_;
```

它的说明书（`callback_group.hpp:150` 起）：

| 原文 | 翻译 |
|---|---|
| The resulting bool will be true in the case that **no** executor is currently using an executable entity from this group. | 如果当前**没有**执行器在用这个组里的东西，它就是 `true`。 |
| The resulting bool will be false in the case that **an** executor is currently using an executable entity from this group, **and the group policy doesn't allow a second take (eg mutual exclusion)** | 如果**有**执行器正在用这个组里的东西，**而这个组的策略不允许「再拿一次」（比如互斥）**，它就是 `false`。 |

**闸门装在哪：** 执行器每一轮先收集"这一轮能跑什么"，收集时挨个组问这句话 ——

`rclcpp/strategies/allocator_memory_strategy.hpp:210`（含上下文）

```cpp
if (!group || !group->can_be_taken_from().load()) {
  continue;                       // ← 门关着，这一组【整个跳过】
}
```

翻译：**门关着，整组跳过。**
「跳过」的意思是：**这个组里的定时器到点了也不管它。**

⚠️ 诚实交底：**把 `false` 写上去的那一步在 `.cpp` 里**（这台机器只装了头文件，
源码不随二进制发布）。但**规则本身头文件写得很清楚**：置不置 `false`，
看的是"**这个组的策略允不允许再拿一次**"。

⭐ 所以"锁"这个词在本关要说准一点：

| 它不是 | 它是 |
|---|---|
| 代码层面的 `std::mutex`（管**数据**） | **执行器层面的一个"能不能拿"的闸门**（管**调度**） |

#### (d) ⚠️ 组身上那把 `std::mutex`，保护的不是你的数据

翻同一个头文件的字段区（`callback_group.hpp:257` 起）：

```cpp
CallbackGroupType type_;                       // 这一组是哪个档
mutable std::mutex mutex_;                     // ← 组身上确实有一把真锁
std::vector<rclcpp::SubscriptionBase::WeakPtr> subscription_ptrs_;   // 名单
std::vector<rclcpp::TimerBase::WeakPtr> timer_ptrs_;                 // 名单
...
std::atomic_bool can_be_taken_from_;           // 上面那道具闸门
```

而用到它的地方在 `:279`：

```cpp
std::lock_guard<std::mutex> lock(mutex_);      // 在 _find_ptrs_if_impl 里
```

| 这把 `mutex_` 保护什么 | 它**不**保护什么 |
|---|---|
| 组里那几份**名单**（`subscription_ptrs_` / `timer_ptrs_` 这些 vector） | **你回调里读写的任何数据** —— 一个字都不管 |

#### (e) 定时器那一拍，**等不等**上一拍？

**不等。** 定时器自己只认两个数：

| 定时器自己**管**的 | 定时器自己**不管**的 |
|---|---|
| 到点了没有 | 上一拍跑完了没有（**它没有"我正在跑"这个状态**） |
| 下一次什么时候到点 —— 从**上一次响**算起 + 周期（第 12 关实测） | 错过的拍子补不补（**不补，也不排队**，第 7 关实测） |

源码里的证据（`rclcpp/timer.hpp`，两步分得很开，**第二步里没有任何守卫**）：

| 行 | 代码 | 干什么 |
|---|---|---|
| `:278` | `rcl_timer_call_with_info(timer_handle_.get(), ...)` | 在 `call()` 里 —— **更新到点时间**（"这一拍我收了"） |
| `:296` | `execute_callback_delegate<>(...)` | 在 `execute_callback()` 里 —— **跑你的函数**，就这一件事 |

翻译成人话：**"到点了"和"有人跑"是两件事，中间那道闸门就是 (c) 里那个布尔。**

#### (f) 两格表：锁那一格的**第四档**

第 13 关那张表（锁 = **组对象的个数**）本关要多一行：

| 组怎么给的 | 组对象几个 | **锁**这一格 |
|---|:-:|:-:|
| 都在默认组（互斥） | 1 | 1 |
| 共用一个自造互斥组 | 1 | 1 |
| 各一个自造互斥组 | 2 | 2 |
| **可重入组** | 1 或 2 | **没有** |

⭐ **可重入组不是在加锁，是在撤锁。**
它改的仍然是**锁**那一格 —— 但改法不是"变成 3"，是**把这一格抹掉**。

> **手那一格它碰都不碰。** 这就是"允许重叠 ≠ 允许并行"：
> 它只是**不再拦你**；真能不能同时跑，还得看**有没有第二只手**（第 12 关的那一格）。

#### (f-2) ⭐⭐ 从"锁那一格填的数"到"这道门是开还是关"—— 换算规则

第 13 关和专项 02 都用了这张表，但**最后那一步换算一直没写在纸上**。
（2026-09-26 补：学习者说"我还是不知道怎么推测" —— 缺的就是这一条，不是缺前提。）

> **这两个回调中间，隔着一把【共用的】锁吗？**
> **隔着 → 锁这道门【关】**　　**不隔 → 锁这道门【开】**

| 锁那一格填 | 中间共用一把锁吗 | 门 |
|---|:-:|:-:|
| **1** | 是（两个回调挂在同一个组对象上） | **关** |
| **2** | 否（各挂一个组对象） | **开** |
| **没有** | 否（根本没有锁） | **开** |

⚠️ 注意这是一句**问句**，不是"数锁的个数"。
在互斥组的世界里两种说法等价，**但碰上可重入组（锁那一格填"没有"）** ——
"数个数"这种说法就**没法用了**（数出 0 个锁，那到底算开还是关？），
只有问句这一种说法还能一路用下去。

**加上第 12 关那半张表，两格才算填完：**

| 手那一格填 | 门 |
|:-:|:-:|
| **1**（单线程容器） | **关** |
| **16**（多线程容器） | **开** |

**最后一步（专项 02 §2.2）：两格全开 = 夹；任意一格关着 = 不夹。**

#### (g) 撤掉锁之后，谁来负责？—— 三个词

| 词 | 定义 |
|---|---|
| **数据竞争**（data race） | 两个线程同时碰**同一块内存**，其中至少一个在**写**，而且没有任何同步 → **结果不可预测** |
| **临界区** | 一段代码，**不能**被两个线程同时执行 —— 碰共享数据的那几行 |
| **原子操作** | 一个**不可分割**的操作，中间不会被别人插进来 |

⚠️ **`count_a_ += 1` 不是一步。** 它在机器上是三步：**读 → 加一 → 写回**。
两个线程各做一遍就可能：都读到 5，都写回 6 —— **自增了两次，只涨了 1。**

要自己补的那把锁（**注意：不是 (c)/(d) 那两个东西**）：

| 写法 | 意思 |
|---|---|
| `std::mutex m_;` | 声明一把锁（**成员变量** —— 跟着对象活） |
| `std::lock_guard<std::mutex> lock(m_);` | 进作用域**自动拿锁**，出作用域**自动放锁** |

> `lock_guard` 的用法叫 **RAII**：把"放锁"绑在"离开作用域"上，
> 于是**你不会忘记放锁**（哪怕中间 `return` 或者抛异常）。

⭐ 一句话收口：**回调组把调度层的锁撤掉了，代码层的锁就得你自己补。** 这是本关真正的作业。

## 2. 核心概念 

### 2.1 可重入组动的是"锁"那一格 —— 而且是**撤锁**，不是加锁

第 12 关的"手"那一格（容器/执行器，住在**进程**里）本关**不动**；本关动的是第 13 关的"锁"那一格（回调组，住在**节点**里）：

| 组的档位 | 锁那一格 = | 组这扇门 |
|---|---|---|
| `MutuallyExclusive`（互斥） | **有一把**（组里所有回调共用） | 组里有回调在跑 → **门关**，整组这一轮被跳过 |
| `Reentrant`（可重入） | **没有** | **永远开** |

⭐ 方向别弄反：`Reentrant` 是**把锁撤掉**（那一格从"有一把"变成"**没有**"），**不是**"再发一把锁"。
撤掉之后，"谁跟谁能同时跑"就只剩【手】那一格说了算。

⭐ 判据的用法（换算成门）：「这两个回调中间，隔着一把**共用的**锁吗？」隔着 → 门关；不隔 → 门开。

### 2.2 重叠要**两条同时**满足

> **重叠 = 【锁 = 没有】×【手 ≥ 2】**

| 只有 | 结果 | 本关哪个实验 |
|---|---|---|
| 锁 = 没有（手不够） | 锁撤了，可没人能来跑第二份 → **不夹** | **实验 D**（单线程） |
| 手 ≥ 2（锁还在） | 手管够，可下一拍被锁挡在门外 → **不夹** | **实验 C**（互斥组） |
| **两条都有** | **同一个回调的两份副本同时在跑** → **夹！** | **实验 B** ⭐ |

### 2.3 判据会失效：**间距才是指纹**

"夹不夹"只能答**是/否**。可当答案是"不夹"时，它**分不出**是锁拦的还是手拦的 —— 本关实验 C 和实验 D 的"不夹"长得一模一样：

| | 不夹的原因 | 下一拍当时在哪 | A 的间距 |
|---|---|---|---|
| 实验 C | 被**锁**挡在门外 | 根本没进候选 | **1.500** |
| 实验 D | 进来了，但**手**先给了别人 | 在候选里排队 | **3.000** |

⇒ 判据（夹不夹）负责**发现**重叠；**间距**负责**区分"到底是谁拦的"**。

### 2.4 定时器没有"我正在跑"这个状态

- `rcl_timer_call_with_info()`（`timer.hpp:278`）在 `call()` 里就把**下次触发时间往前推了** —— 它不会等你的回调回来。
- `execute_callback()`（`timer.hpp:296`）只是**调用你的函数**。

⇒ 所以定时器的**周期**和回调的**耗时**是两个独立的东西：回调睡 1.5 秒，周期还是 1 秒 —— 到期照旧到期。至于它能不能**上得了手**，那是"手"和"锁"两格的事。

### 2.5 重叠的指纹：**日志标签错位**

`count_a_ += 1` 是「读 → 加一 → 写回」三步，中间**没有原子性**。两份副本都读到同一个数，打印出来的拍号就和**实际副本**对不上：

- 实验 B 里 `731.534991864` 那行印的是「A **第2拍** 睡醒了」，可它其实是**第 1 份副本**醒过来（第 2 份要到 732.5349 才醒）。
- 那个"多出来的 1"，就是另一份副本在它睡着的 1.5 秒里**插进来加过**的。

⇒ 这是**数据竞争**（data race）的可见证据：多个线程同时碰一个非原子的变量，程序行为没有保证。

## 3. 完整代码 

本关定稿版（就是第 13 关的仪器，只改了 4 行 —— 编号 ①②③④ 就是这 4 行）：

```cpp
#include <chrono>
#include <memory>

#include "rclcpp/rclcpp.hpp"
#include "rclcpp_components/register_node_macro.hpp"

using namespace std::chrono_literals;


// 第 12/13 关的"测速仪"：一个专门用来占住执行器的手的组件。
// 它不发布任何东西，只在定时器回调里睡一觉 —— 睡觉这段时间它攥着那只手不放。
//
// 第 13 关给它加了【第二个】定时器（tick_b），并且把两个定时器分别挂到
// 【两个独立的互斥回调组】上 —— 定时器两个，锁两把。
// 第 14 关把这两把锁【撤掉】：两个组都换成 Reentrant（可重入）。
class Sleeper : public rclcpp::Node
{
public:
    Sleeper(const rclcpp::NodeOptions & options) : Node("sleeper", options)
    {
        count_a_ = 0;
        count_b_ = 0;
        group_a_ = this->create_callback_group(rclcpp::CallbackGroupType::Reentrant);  // ①
        group_b_ = this->create_callback_group(rclcpp::CallbackGroupType::Reentrant);  // ②
        timer_a_ = this->create_wall_timer(1s, [this]() { tick_a(); }, group_a_);
        timer_b_ = this->create_wall_timer(1s, [this]() { tick_b(); }, group_b_);
    }

private:
    void tick_a()
    {
        count_a_ += 1;
        RCLCPP_INFO(this->get_logger(), "A 第%d拍 开始睡", count_a_);

        // 睡觉这段时间，它攥着执行器的那只手不放 —— 这就是本关的"测速仪"
        rclcpp::sleep_for(1500ms);   // ③

        RCLCPP_INFO(this->get_logger(), "A 第%d拍 睡醒了", count_a_);
    }

    void tick_b()
    {
        count_b_ += 1;
        RCLCPP_INFO(this->get_logger(), "B 第%d拍 开始睡", count_b_);

        rclcpp::sleep_for(1500ms);   // ④

        RCLCPP_INFO(this->get_logger(), "B 第%d拍 睡醒了", count_b_);
    }

    rclcpp::TimerBase::SharedPtr timer_a_;
    rclcpp::TimerBase::SharedPtr timer_b_;
    rclcpp::CallbackGroup::SharedPtr group_a_;
    rclcpp::CallbackGroup::SharedPtr group_b_;
    int count_a_;
    int count_b_;
};

RCLCPP_COMPONENTS_REGISTER_NODE(Sleeper)
```

|---|---|---|---|---|
| ① ② | 22 / 23 | `MutuallyExclusive` | **`Reentrant`** | **第 14 关**（撤锁） |
| ③ ④ | 35 / 45 | `500ms` | **`1500ms`** | 第 14 关（觉 > 周期，重叠才够得着） |


**三档精度**：小数**第 1 位**看量级（0.5 / 1.0 / 1.5）→ 小数**前 3 位**报数字（毫秒级）→ **整行交给 python**（微秒级的怪东西，比如 0.0001 秒的接棒）。

| 量的东西 | 两行 | 结果 |
|---|---|---|
| 觉 | 316.180638425 − 314.680232431 | **1.5004 秒** |
| 接棒（B 睡醒 → A 上） | 316.180710931 − 316.180638425 | **0.000073 秒** |
| **A 自己两拍** ⭐ | 319.181328565 − 316.180710931 | **3.0006 秒** ← 预测 3.000 ✅ |
| B 自己两拍 | 317.680963368 − 314.680232431 | **3.0007 秒** |
| 夹不夹 | A 第1拍醒(317.680831168) 早于 A 第2拍上(319.181328565) | **不夹** ✅ |

**结论**：⭐⭐ **可重入 + 单线程 → 不夹**，可这**不是因为锁**（锁已经撤了，门全程开着）——
是**因为只有一只手**：手正攥在 A 的第 1 拍里，谁都上不来。
⇒ **"可重入"这张通行证本身造不出重叠**；要真重叠，**还得有第二只手**（回到 §2.2 那条式子）。
⇒ 新规矩：**回调比周期长的时候，一只手会把间距翻倍**（1.000 → **3.000**）—— 因为除了 A 自己，**还有 B 在排队**，手一空先给了 B。

### 四关对表（本关的总结）

| 实验 | 手 | 锁 | 夹自己？ | A 的间距 | 半路拦它的是 |
|---|:-:|:-:|:-:|:-:|---|
| A | 多 | 有 | 不夹 | 1.000 | 时间没到（0.5 < 1.0） |
| B | 多 | **没有** | ⭐ **夹了** | 1.000 | 没人拦 |
| C | 多 | 有 | 不夹 | **1.500** | **锁** |
| D | **1** | 没有 | 不夹 | **3.000** | **手** |

**三条结论：**

1. **重叠 = 【锁 = 没有】×【手 ≥ 2】** —— 两条同时满足才夹得起来（B 满足，C 缺前者，D 缺后者）。
2. ⭐ **"夹不夹"会在 D 上失效**：C 和 D 都答"不夹"，可拦路的一个在锁上、一个在手上。
   **只有"间距"（1.500 vs 3.000）能把它们拆开** —— 判据负责发现，间距负责区分。
3. **撤锁不等于重叠**：D 把锁撤了，什么都没有发生 —— 通行证发了，没有第二只手来用。

### 附：一个还没解释的现象 —— 为什么总是 **B 先上**？

四个实验**全部**是 `B 第1拍 开始睡` 排在 `A 第1拍` 前面（第 13 关那两次单线程跑也是），单线程里还一直是 `B, A, B, A…` 的固定交替。

- 跟"谁先创建定时器"**无关**（A 是先创建的那个，`timer_a_` 在 `timer_b_` 前面）。
- 源码里能看到名单的容器是**按指针地址排序**的映射：

```
memory_strategy.hpp:46
using WeakCallbackGroupsToNodesMap = std::map<CallbackGroup::WeakPtr, …, owner_less>;
```

⇒ 名单顺序由**两个回调组对象的地址**决定 —— 写代码时看不见，**等于随机，但定下来就不变**。
⇒ 所以**能预测的是【交替】和【间距】**，**预测不了"先给 A 还是先给 B"**。
⚠️ 这一条是**读源码 + 日志吻合**推出来的，**还没做实验去证**（存疑，记在 §10）。

## 8. 踩坑记录 

### 坑 1：`source` 又忘了 —— `Could not find requested resource in ament index`（第 3 次复发）

装组件时：`Failed to load component: Could not find requested resource in ament index`

- **翻译**：在 ament 索引里**找不到你要的东西**。
- **原因**：没 `source ~/ros2_learn_ws/install/setup.bash`，`ros2 component load` 不知道 `hello_ros_cpp` 装在哪。
- **正确顺序**：`colcon build` → `source` → 再开容器/装组件。
- ⚠️ **第 11 关坑 6、第 13 关也栽过一次，这是第 3 次**。

### 坑 2：只拧了**半个旋钮**（本关连续两次）

| 次数 | 现场 | 后果 |
|---|---|---|
| 第 1 次 | 实验 B 只把【组】换成 `Reentrant`，两根 `sleep_for` 都还是 `500ms` | 量到的是"实验 A"的数据，白跑 |
| 第 2 次 | 只把第 35 行改成 `1500ms`，第 45 行还是 `500ms` | 日志里 B 只睡 0.5004 秒（从时间戳一眼看穿） |

- **怎么发现的**：不看代码，**看时间戳** —— B 的觉是 `0.5004` 秒，和"说好的 1500ms"对不上。
- ⭐ **规矩（已写进 §6 验收清单第 4 条）**：跑之前，先把"这个实验的前提是哪几个数"**写下来**，回源码**对一遍**：
  - 周期 = `1s` × 2 个定时器
  - 觉 = `1500ms` × 2 个定时器

### 坑 3：`.so` **不会热重载**

容器**开着**的时候 `colcon build`，容器里跑的**还是旧 `.so`** —— 不会自动换。

- ⇒ 改完代码：**先 Ctrl+C 杀掉容器**，再 build，**再重新起容器**、重新 `load`。
- ⚠️ 危险点：新旧 `.so` 的**装载三行日志一模一样**，光看装载回执**分不出**跑的是哪个 —— 唯一的分辨办法是**看现象的差别**（比如"可重入才会自我重叠"这个只有新版本才做得出来）。

### 坑 4（我的）：预习节里没写"锁 → 门"的换算规则

§0 写了"两格的表"，却没写**怎么把"锁"那一格换算成门开/门关**，学生卡在"我还是不知道怎么推测"。

- **补的规则**（§2.1 末）：问「这两个回调中间，隔着一把**共用的**锁吗？」隔着 → 关；不隔 → 开。
- ⚠️ 这是第 13/专项 02 §7 那一族坑的**复发**：**表格给了，换算没给**。下次做"两格的表"，**表后面必须紧跟一行换算规则**。

### 坑 5：判据不够用（不是坑，是本关最大的收获）

只盯"夹不夹"，**实验 C 和 D 会给出同一个答案**。是**间距**把它俩分开的 —— 已升格为结论（§2.3 / §7 结论 2）。
